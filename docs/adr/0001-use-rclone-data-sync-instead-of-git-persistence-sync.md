# Use rclone data sync instead of Git persistence sync

GTD on Rails synchronizes the whole `gtd.data.root-directory` with `rclone` instead of synchronizing the SQLite database through Git. The SQLite database, Google integration configuration, assets, and `gtd-on-rails-sync-check` dataset marker live in that root; startup data sync blocks before SQLite opens so the app does not start from stale local data. When the marker is missing, bootstrap treats the remote as the source with `--resync`; the backend publishes the marker before normal sync starts using `--check-access`. First publication or migration of local data to the remote remains a manual operation. Google Integration Configuration saves are local writes followed by asynchronous data sync, not sync-blocking transactions with rollback. This deliberately favors a simpler single transport over Git commit history and can be revisited if direct SQLite file synchronization shows consistency problems.
