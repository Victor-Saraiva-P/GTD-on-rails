# Use Caffeine in-memory cache and optimistic UI

GTD on Rails will introduce a local in-memory caching layer in the Spring Boot sidecar alongside optimistic UI state in the Tauri React desktop client. The sidecar uses Spring Cache backed by Caffeine with a 5-minute time-to-live and region-wide cache evictions on entity mutations. Read queries (`/inbox`, `/next-actions`, `/projects`, `/contexts`, `/calendar`) are served from local sidecar memory in sub-millisecond time rather than incurring round-trip WAN latency to remote Supabase PostgreSQL instances on every keystroke and filter change. The desktop client applies immediate optimistic updates for high-frequency keyboard operations (such as marking items done, moving to on-going, deleting, and patching attributes) while persisting synchronously through the sidecar to PostgreSQL with automatic snapshot rollback upon network failure.

Cache regions are partitioned by domain aggregates: `inbox`, `nextActions`, `projects`, `contexts`, and `calendar`. Cross-aggregate mutations (such as converting stuff to next actions or projects) trigger region-wide evictions (`allEntries = true`) across affected aggregates. To ensure instant navigation immediately upon desktop startup, the sidecar triggers background pre-warming of active datasets once database readiness reaches `READY`. An explicit maintenance endpoint (`POST /maintenance/cache/evict`) and full cache clearing on dataset reset allow forced cache eviction when needed.

This preserves the single-user transactional consistency and security guarantees of remote PostgreSQL without requiring complex distributed offline synchronization engines, while restoring sub-millisecond responsiveness required by a keyboard-driven vim-like desktop interface.
